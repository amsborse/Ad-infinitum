2016 → 2026

Same research question — different infrastructure. We keep the historical kernel module; new work runs on mainline F2FS.

📁 2016 (Original)

  • Kernel: Linux 4.1.8 fork in gc.c
  • Policies: Forced GREEDY in code (buggy trial)
  • Observe: printk(KERN_ERR) → dmesg
  • Metric: Compilebench system time only
  • Fix: policy2 FG_GC early-exit patch
  • Published: IJTRD survey

⚡ 2026 (This edition)

  • Kernel: Mainline 5.10+ via sysfs
  • Policies: Greedy / CB / ATGC toggles
  • Observe: ftrace + tools/trace-gc.sh
  • Metrics: p99 latency, IOPS, GC events, WA
  • Fix: migration_window_granularity + reference patch
  • Repro: tools/run-experiment.sh + fio jobs

Tooling

Research toolchain

Replaces the 2016 printk branches with reproducible scripts.

tools/trace-gc.sh

ftrace capture + sysfs policy snapshot. Replaces printk-1.

sudo ./tools/trace-gc.sh -d /mnt/f2fs -t 120

tools/run-experiment.sh

Full policy × utilization matrix with fio.

sudo ./tools/run-experiment.sh -d /mnt/f2fs -p all -u 90 -r 5

tools/summarize-results.py

Parse fio JSON → p50/p95/p99 table.

python3 tools/summarize-results.py

patches/policy2-*.patch

Reference port of 2016 FG_GC early-exit for A/B testing.

patch -p1 < patches/policy2-fg-gc-early-exit.reference.patch
